## Critical（必须修复）

### [F-CR-001] scripts/lib/workflow_continue.py:349-366 (_advance_after_completed) + standard-8phase.yaml

DAG 首节点完成后 `_advance_after_completed` 调 `_next_node(node, result.next_node_hint)`，DAG yaml 节点无 `next` 字段且 hint 默认 None → 返 None → current_node 置 None → `_main_loop` while 退出。判决独立验证：(1) workflow_continue.py 全文 grep `_select_next_dispatch_target` 调用点为 0；(2) test_legacy_next_chain.py:79 测试自身需手动 bootstrap 才能跑通——反向证明生产路径缺口。**等效于 DAG workflow 仅跑首节点即终止，功能未上线**。

**建议**：`_advance_after_completed` 末尾按 `workflow.get('depends_on_explicit')` 分流：True 时调 `_select_next_dispatch_target` → 取 ready[0]；False 时保持 `_next_node` 单链推进。必须新增 main_loop 多节点 e2e 测试（fixture: 3 节点 DAG，A→B / A→C，覆盖 A 完成 → 派 B / C 完整链路）。

## Major（强烈建议修复）

### [F-CR-002] scripts/lib/workflow_continue.py:520-546 (_main_loop) + 674-713 (main)

`main()` 调用链 `_setup_run → _resume_run → _main_loop`，无任何节点调 `_select_next_dispatch_target` 设 current_node。`_main_loop` while 542 条件要求 current_node 真值——对真新 run（current_node is None），整个 while 直接跳过，workflow 一次都不前进。test_legacy_next_chain.py:78-80 注释明确说『F-004：用 _select_next_dispatch_target 选首节点』，并紧接着调 _main_loop，正是测试基础设施替生产代码做的 bootstrap。

**建议**：在 `_main_loop` 入口（finalize_after_rebuild 之后、while 之前）补 bootstrap：若 current_node is None 且 state==running，调 `_select_next_dispatch_target`；返 None 则不进 while（已被 finalize 接管），否则置 current_node 进入循环。

### [F-CR-003] scripts/lib/workflow_continue.py:109-164 (_select_next_dispatch_target)

CCN=17 > 阈值 10。F-CR-001 修复落地后该函数将成为热路径，复杂度膨胀风险更高。

**建议**：拆三子函数：`_dag_next`（depends_on_explicit 分支）/ `_legacy_bootstrap_or_resume`（current_node is None 双分支 a/b）/ `_legacy_advance`（current_node 非空单链推进）。目标 CCN ≤ 8。

### [F-CR-004] scripts/lib/workflow_continue.py:452-517 (_finalize_after_rebuild_if_last_topology_node)

CCN=18 > 阈值 10。F-004 新增 DAG 分支（497-509，5 个新条件）贡献主要复杂度增量。

**建议**：抽 `_is_dag_topology_done(workflow, run_state) -> bool` 和 `_is_legacy_topology_done(last_node) -> bool` 两个 helper，主函数仅做分流。

### [F-CR-007] scripts/lib/workflow_continue.py:493-495 (_finalize_after_rebuild_if_last_topology_node)

反扫 last_visited_id 拿到节点 id 后 `node_map.get(last_visited_id)` 静默 return False，无 WARN。该分支触发条件：jsonl 写了 last_visited_id 但 yaml 已无该节点（迁移 / rename / 删节点）——这是 spec 严重事件。**F-004 新引入分支，非存量**。
