## 需求描述

scripts/lib/workflow_status.py 加 --verbose flag（D-002 树形文本）；输出含 ready/running/blocked/paused/awaiting/done 节点分类（基于 run_state.node_outputs + workflow.nodes 计算）。stale 检测：RunState.last_event_ts 距 now ≥ STALE_THRESHOLD_MINUTES（默认 30，env CLAUDE_WORKFLOW_STALE_MINUTES override，D-010）→ WARN line。blocked 节点附 reason（deps 列表）；awaiting 节点附 kind（反扫末位 node_ready / approval_repair_started 判定）。落地 ADR D-002 + D-010 + D-011 + AC-06。

## 验收标准（features.json `acceptance`）

- [ ] --verbose 输出含 ready (N) / running (N) / blocked (N) / awaiting (N) / done (N) 五行分类
- [ ] blocked 节点附 'deps: [a, b]' 说明阻塞依赖；reason 取自 {incomplete_dispatch, awaiting_deps, awaiting_claude_action} 枚举
- [ ] awaiting 节点附 'kind=skill_result' 或 'kind=approval_repair'
- [ ] last_event_ts 距 now ≥ 30 分钟 → 输出含 'WARN: stale heartbeat (age=Xmin)'
- [ ] env CLAUDE_WORKFLOW_STALE_MINUTES=1 + 2 分钟前 ts → 立即 stale
- [ ] 无 --verbose → 输出格式与既有 status 一致（不破坏 D-007 双轨已有 fixture）
- [ ] e2e：fixture 写 approval_pending 事件 + 30 分钟前 ts → status --verbose 输出含 stale WARN
- [ ] e2e：jsonl chmod 000 → status --verbose exit != 0 + stderr 含 jsonl unreadable
- [ ] e2e incomplete_dispatch 诊断（v8 REV-007 P2 闭环 AC-06 e2e (b)）：fixture 写 [workflow_started, node_started(N1)] 但**无后续 node_completed / node_failed / node_skipped 事件** → status --verbose 输出含 'blocked: incomplete_dispatch' 行 + 'node: N1'（对应 requirement.md:106 e2e 场景 b）
