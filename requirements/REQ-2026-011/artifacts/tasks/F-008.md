# F-008 · path_lock 三件套 + 双轨 symlink + workflow_continue 入口取锁

## 需求描述

新建 scripts/lib/path_lock.py：acquire(run_id, repo_root) → LockHandle / release(handle)；fcntl.LOCK_EX + LOCK_NB；lock 文件 JSON 含 pid + created_at + path_target + host。失败 → 读 lock JSON → _is_pid_alive(pid)：ESRCH 自动清理 + 重试一次；活着 → raise LockBusyError。requirement 类 run（run_id 以 REQ- 开头）建 requirements/.locks/<req-id>.lock symlink；用 os.path.lexists 检测（不是 exists，避免 dangling 误报）；release 时不删 symlink。atexit + SIGTERM handler 兜底删 .lock 文件。scripts/lib/workflow_continue.py main() 入口在 _setup_run 之后 _resume_run 之前调 acquire。落地 ADR D-003 + AC-05。

## 验收标准（features.json `acceptance`）

- [ ] acquire 首次取锁成功 → runs/.locks/REQ-2026-099.lock JSON 含 pid==os.getpid() / created_at(ISO8601) / path_target(绝对路径)
- [ ] requirement 类 run → requirements/.locks/REQ-2026-099.lock 是指向实锁的 symlink；用 os.readlink 校验
- [ ] release 后 .lock 文件被删；symlink 保留（dangling 容忍）
- [ ] 并发：进程 A 持锁，进程 B 100ms 内取锁 → raise LockBusyError + stderr 含 'another continue is running, pid=<A>' + exit 1
- [ ] 残锁：mock _is_pid_alive=False → 自动清理 .lock 重试一次成功
- [ ] 残锁 + 重试后仍冲突（极小概率）→ raise LockBusyError，不进入活锁
- [ ] atexit：进程 sys.exit(0) → .lock 文件被删（pytest tmp_path 验证）
