## 需求描述

scripts/lib/workflow_loader.py 的 _expand_implicit_depends_on 内补 workflow['depends_on_explicit']: bool 标记位（True = 全部节点显式声明 depends_on；False = 至少一节点缺省，loader 自动补 [prev_id]）。**全局成功终态集合 SUCCESS_TERMINAL = {completed, skipped}**（v8 REV-007 P1 抽出贯穿）：用于依赖满足判定 / 退化路径 last_visited / DAG finalize；implementation 阶段抽到 scripts/lib/run_state.py 共享常量永久消除复发风险。scripts/lib/workflow_continue.py 新增 _ready_nodes(run_state, workflow)（D-013 每次全量重算；依赖满足条件 = deps 全部 ∈ SUCCESS_TERMINAL；跳过状态 ∈ SUCCESS_TERMINAL ∪ {failed, running, awaiting_claude_action}，**v8 P1 修订前只看 completed 会让 skipped 依赖永久阻塞下游 + skipped/failed 节点被错误重派**）+ _select_next_dispatch_target() 双路径分流。**退化路径双分支兜底**：(a) current_node is None ∧ 无任何 success_terminal 节点 → 返回 yaml.nodes[0].id（真新 run）；(b) current_node is None ∧ 已有 success_terminal 节点 → 反扫 node_outputs 取 last_visited（含 completed/skipped）→ 走 _next_node(last_visited)。_finalize_after_rebuild_if_last_topology_node DAG 末节点判定：全节点 ∈ SUCCESS_TERMINAL ∧ 不存在 failed ∧ _ready_nodes 为空 → 才写 workflow_completed；含 failed 节点时返回 False 由 _route_outcome 失败矩阵接管。**单链路径 finalize 反扫起点同步改 last_visited（含 node_completed/node_skipped 事件）**——v7 反扫 last_completed 在末节点 skipped 时会漏写 workflow_completed。落地 ADR D-006 + D-013 + AC-01 + 详见 detailed-design.md §3.3.5 / §3.4 / §3.6.2 / §3.6.3 / §5.4。**`.claude/workflows/requirement/standard-8phase.yaml:57` 的 `check_meta_schema.py` → `check_meta.py` 修订归 F-005**（语义属 AC-02 R-I03，本 task touches 已移除 yaml，详见 plan.md ADR D-015）。

## 验收标准（features.json `acceptance`）

- [ ] loader：全显式 depends_on yaml → workflow['depends_on_explicit'] == True
- [ ] loader：任一节点缺省 depends_on → workflow['depends_on_explicit'] == False（loader 仍补 [prev_id]）
- [ ] _ready_nodes 首次调用（success_terminal=∅）→ 返回入度=0 节点集（按 yaml 出现顺序）
- [ ] _ready_nodes 依赖满足判定用 SUCCESS_TERMINAL（{completed, skipped}，v8 REV-007 P1 修订）：某节点 deps 全部 ∈ SUCCESS_TERMINAL → 加入 ready；已在 success_terminal / failed / running / awaiting → 不加入
- [ ] v8 P1 反向回归 a（skipped 不阻断下游）：yaml N1 → N2（N2.depends_on=[N1]），事件 [..., node_skipped(N1)] → _ready_nodes 返回 ['N2']（旧实现误返 [] 让 N2 永久阻塞）
- [ ] v8 P1 反向回归 b（finalize 末节点 skipped）：单链 yaml N1→N2→N3，事件 [..., node_completed(N1), node_completed(N2), node_skipped(N3)]（N3 是末节点）→ _finalize_after_rebuild_if_last_topology_node 反扫 last_visited=N3，_next_node(N3,None) is None → 补写 workflow_completed（旧 last_completed 反扫 N3 是 skipped 被漏，会卡死）
- [ ] _select_next_dispatch_target：depends_on_explicit=True → 调 _ready_nodes 取 [0]；False → 调 _next_node；**退化路径 current_node is None ∧ 无 success_terminal 节点 → 返回 workflow.nodes[0].id（P1-2 分支 a）**；**退化路径 current_node is None ∧ 有 success_terminal 节点 → 反扫 last_visited → _next_node(last_visited)（P1-2 v6 分支 b 修复 + v8 P1 命名对齐）**
- [ ] 新 run 启动断言（P1-2 分支 a 回归）：仅 [workflow_started] 事件 + 退化 yaml（depends_on_explicit=False，3 节点 N1/N2/N3）→ _select_next_dispatch_target 返回 'N1'（首节点 id）
- [ ] 续跑反扫断言（P1-2 分支 b 回归，v6 新增 + v8 命名修订）：[workflow_started, node_started(N1), node_completed(N1)] + 退化 yaml（N1.next=N2）→ rebuild 后 current_node is None ∧ node_outputs[N1].state=='completed' → _select_next_dispatch_target 反扫得 last_visited=N1 → 返回 'N2'
- [ ] 末节点反扫断言（P1-2 分支 b 边界）：[..., node_completed(N3)] + N3 是末节点（无 next） → 反扫得 last_visited=N3 → _next_node(N3, None) is None → 返回 None（交 _finalize_after_rebuild 处理）
- [ ] skipped 反向回归（v7 REV-006 P1 闭环，对称 P1-3）：[workflow_started, node_started(N1), node_skipped(N1, reason='on_failure=skip')] + 退化 yaml（N1.next=N2）→ rebuild 后 current_node is None ∧ node_outputs[N1].state=='skipped' → 分支 a any_visited=True（含 skipped）→ 进入分支 b → 反扫得 last_visited=N1 → 返回 'N2'。**关键反向**：N1 不会被错误重新派发首节点（v6 漏 skipped 时会回到首节点）
- [ ] e2e：fixture workflow_legacy_next.yaml（5 节点全用 next）跑通退化路径，jsonl 末位 workflow_completed
- [ ] e2e：standard-8phase.yaml 走 DAG 路径首节点 bootstrap-validate 跑通，第二层 ready 计算正确
- [ ] _finalize_after_rebuild_if_last_topology_node DAG 路径（P1-3 v6 修订）：**全节点 ∈ {completed, skipped} 且不存在 failed 且 _ready_nodes 为空时**才补 workflow_completed；含 failed 节点 → 返回 False（不写 workflow_completed，交失败矩阵接管）；单链末节点 _next_node is None → 同款补完成事件
- [ ] 多 sink DAG 反向回归（P1-3 反向覆盖）：fixture 含 2 个并行 sink A 与 B（depends_on_explicit=True，A.depends_on=B.depends_on=[N0]），node_completed(A) 单独写入后 _finalize_after_rebuild_if_last_topology_node 返回 False；直到 node_completed(B) 写入后才返回 True 并补 workflow_completed
- [ ] 含 failed 节点反向回归（P1-3 v6 新增）：fixture 含 3 节点 N1/N2/N3，事件序列 [..., node_completed(N1), node_failed(N2), node_completed(N3)]，rebuild 后 node_outputs={N1:completed, N2:failed, N3:completed} → _finalize_after_rebuild_if_last_topology_node 返回 False（不写 workflow_completed；workflow_failed 由 dispatcher 失败矩阵在 _route_outcome 的 abort/skip 分支决定）
