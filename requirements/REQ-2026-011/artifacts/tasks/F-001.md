# F-001 · append_events 批量原子 + 4KB 上限 + manifest-pointer fallback

## 需求描述

新建 scripts/lib/append_events.py。提供 append_events(jsonl_path, events) 单次 LOCK_EX + 单次 os.write 多条事件原子写（R-T03 根除），常量 MAX_BATCH_PAYLOAD_BYTES=4096 / MAX_INLINE_FIELD_BYTES=3500。payload 累计 ≥ 4KB 抛 PayloadTooLargeError。提供 append_events_with_manifest(...) **二段触发** 算法（对抗审阅 P2 v6 修订）：先 dry-run 估算 batch 序列化字节数，若 batch <4KB → 直写 jsonl（即使有 3.6KB 单字段）；若 batch ≥4KB → 扫描 large_field_paths，单字段 ≥3500 字节 (MAX_INLINE_FIELD_BYTES) 入选落 runs/<id>/manifest/<event_id>.txt + jsonl event 仅留 {path,size,sha256} ref。manifest 写采用 tmp + fsync + os.replace 顺序。落地 ADR D-014 + AC-A1 baseline，作为 F-006 / F-007 等批量写场景的底层依赖。

## 验收标准（features.json `acceptance`）

- [ ] 3 事件 payload 总 < 4KB → 单次 LOCK_EX 写入 jsonl，事件数 / 顺序与传入一致
- [ ] 5KB payload → raise PayloadTooLargeError 且 jsonl 无副作用
- [ ] reject reason 5KB 走 append_events_with_manifest → manifest/<event_id>.txt 存在 + index.txt 追加一行 + jsonl event.data.reason_ref={path,size,sha256}
- [ ] manifest tmp 写失败 → 不写 jsonl，raise OSError，不产生半落盘
- [ ] 事件 type 不在 VALID_EVENT_TYPES → raise WorkflowError 与既有 append_event 一致
- [ ] manifest/index.txt 多进程并发 append 原子：起 2 个子进程同时调 append_events_with_manifest 各写 1 条 5KB reason → index.txt 含 2 行且 sha256 与 manifest/<event_id>.txt 文件内容一致（用 fcntl.LOCK_EX 锁 index.txt fd，覆盖 R-5 风险）
- [ ] v6 P2 反向回归：单字段 3.6KB（≥3500 但 batch <4KB）→ append_events_with_manifest 直写 jsonl 不落 manifest（manifest 目录无新文件，event 仍保留 inline 字段；与 §2.4 + §3.5 二段触发对齐）
