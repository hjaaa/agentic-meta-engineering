## Major（强烈建议修复）

### [error-handling] scripts/lib/signoff.py:454-458

verdict 写盘 `tmp_path.open / json.dump / tmp_path.replace` 三步无任何 try/except。CR 校验通过后若磁盘满或权限错会抛 OSError 中断 + 留 `.json.tmp` 残留在 reviews/ 目录，调用方无法区分"写盘失败"与其他 rc。

**建议**：参考 `_append_signoff_process_log:191-197` 的 OSError 处理模式：

```python
try:
    with tmp_path.open("w", encoding="utf-8") as f:
        json.dump(verdict, f, ensure_ascii=False, indent=2)
        f.write("\n")
    tmp_path.replace(verdict_path)
except OSError as exc:
    tmp_path.unlink(missing_ok=True)
    print(paint(f"❌ verdict 写盘失败（{exc}）", "red"), file=sys.stderr)
    return 1
```

### [design-consistency] scripts/lib/signoff.py:11

模块 docstring L11 措辞与 `__all__` 语义反向：

```
> 禁止其他模块通过 from signoff import * 引入这两个符号
```

`__all__ = ['run_signoff', 'build_signoff_parser']` 标准 Python 语义恰是「允许 import * 时暴露这两个符号」。

**建议**：改为：

```
__all__ 将公开 API 限定为 build_signoff_parser 与 run_signoff；
from signoff import * 仅引入这两个符号（不含私有 helper）。
禁止直接 python3 -m signoff 启动。
```
