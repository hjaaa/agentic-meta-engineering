## Minor（改进建议 — 6 条 keep）

### [design-consistency / documentation] doc-drift（H-1 + H-13 合并）

`detailed-design.md:96` §1.2.5 + `.claude/skills/managing-workflow-runs/reference/command-implementations/list.md:29` + `workflow_list.py:120` docstring 三处仍写"exit 2"，但 G-31 已把代码改为 exit 1。

**建议**：全仓 grep `exit 2` 字面值统改为 exit 1（保留 approve/reject 非 tty fail-closed 专属）。

### [error-handling] OSError-not-wrap（H-7 + H-14 合并）

- `scripts/lib/run_state.py:281-294` append_event 内 `os.open` / `fcntl.flock` / `os.write` 链路上 OSError（磁盘满 / 权限不足）不 wrap WorkflowError
- `scripts/lib/workflow_run.py:121-128` yaml.safe_dump / json.dump 写 meta.yaml 同性质
- 上游 workflow_save / continue / approve / reject / cancel 多处 except WorkflowError 不 catch OSError → 用户看到 Python traceback

**建议**：在 append_event try/finally 外层加 `except OSError as exc: raise WorkflowError(f'写 jsonl 失败: {exc}') from exc`；workflow_run.py meta 写入同处理。

### [error-handling / complexity] except-tuple-redundant

`workflow_list.py:62, 71` `except (json.JSONDecodeError, Exception) as exc2`：Exception 已包含 JSONDecodeError 元组冗余，且 Exception 过宽违反 G-12 缩窄规则。

**建议**：改为 `except (json.JSONDecodeError, OSError) as exc2`。

### [concurrency / observability] eexist-no-log

`scripts/lib/workflow_run.py:50-58` G-8 EEXIST 重试无日志；并发冲突这种边角路径不可观测，无法事后诊断是否触发了重试。

**建议**：`except FileExistsError: logging.debug('run_id %s 冲突，递增重试 attempt=%d', candidate_id, attempt); next_num += 1`（与 common.py:51 同模式）。

### [error-handling] status-fixed-msg

`scripts/lib/workflow_status.py:55-56` 子 run 解析 `except WorkflowError` 文案固定写"目录不存在"丢失原 exc 信息（WorkflowError 也可能因 run_id 非法而抛）。

**建议**：改为 `except WorkflowError as exc: lines.append(f'... 子 run {sub_run_id!r} 解析失败: {exc}')`。
