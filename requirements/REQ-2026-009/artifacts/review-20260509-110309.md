## Major（强烈建议修复 — 4 条 keep）

### [concurrency] scripts/lib/workflow_run.py:24-40 / `_generate_run_id`

`_generate_run_id` 三步非原子：iterdir 取已有目录列表 → 计算 max+1 → `mkdir(parents=True, exist_ok=True)`。两个并发 `/workflow:run` 进程会扫到相同的 max，生成相同 run_id；`mkdir(exist_ok=True)` 不报错→共享同一目录互覆盖 meta.yaml 与 jsonl。CLI 单进程概率低但非零（user 双开 terminal / CI 并发）。

**建议**：用 `mkdir(exist_ok=False)` + EEXIST 重试循环（最多 3 次取 next_num+1）；或加 filelock(`runs/.lock`) 串行化生成。

### [error-handling] scripts/lib/workflow_cancel.py:120

```python
try:
    append_event(jsonl_path, {...})
except WorkflowError:
    pass  # ← 完全无声
```

TaskStop 失败 → WARN stderr → 试写 cancel_taskstop_failed → 失败仍 pass 无任何输出。已经处于降级路径还吞最后一条审计事件失败，用户与审计两层都看不到。

**建议**：改为 `except WorkflowError as exc2: print(f'WARN: 写 cancel_taskstop_failed 事件也失败：{exc2}', file=sys.stderr)`。

### [error-handling] scripts/lib/workflow_continue.py:87

```python
try:
    append_event(jsonl_path, {"type": "run_resumed", ...})
except WorkflowError as exc:
    print(f"WARN: 写 run_resumed 失败：{exc}", file=sys.stderr)
    # 不阻断续跑流程，仅 warn
```

run_resumed 是 continue 命令的核心审计事件（spec §1.2.2 步骤 5），写失败仅 WARN 后 main exit 0；审计层 run lifecycle 丢失而调用方无感。对照 cancel.py:93 写 cancel_requested 失败 exit 1 的处理，同类审计事件应同处理。

**建议**：审计事件写失败应 exit 1（与 cancel_requested 同），或至少 print(file=sys.stderr) + 显式日志级别 ERROR。

### [error-handling] scripts/lib/workflow_list.py:55-61

```python
try:
    meta = yaml.safe_load(meta_path.read_text("utf-8")) or {}
except Exception:
    try:
        import json
        meta = json.loads(meta_path.read_text("utf-8"))
    except Exception:
        meta = {}
```

双层 `except Exception` 吞 yaml.YAMLError + json.JSONDecodeError，meta 损坏时 list 表格 template/phase 显示空字段而非告警，调试困难。

**建议**：`except (yaml.YAMLError, json.JSONDecodeError) as exc: print(f'WARN: meta 解析失败 {run_dir.name}: {exc}', file=sys.stderr)`，缩窄 except 范围 + 显式 stderr。
