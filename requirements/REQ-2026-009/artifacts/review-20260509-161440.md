## Major 问题（5 项 · keep · 必修）

### F-1 · 锁顺序与 §6.4 不符 [concurrency + design_consistency]

- 路径：`scripts/lib/workflow_rollback.py:728-737`
- critic verdict: `not_rebutted`
- 描述：实现先 `mkdir(archive_root)`（行 730-731）→ 后 `_acquire_dual_lock`（行 737）；§6.4 伪码（detailed-design.md:843-855）顺序是 flock → mkdir → O_EXCL。`.in_progress` O_EXCL 是兜底但非根治，同秒并发场景下两进程可 mkdir 同一 ts 目录。
- 修复建议：
  ```python
  # 先 acquire flock
  lock_fd = _acquire_flock(lock_path)
  try:
      # 持锁后再生成 ts + mkdir + O_EXCL .in_progress
      archive_ts = _make_archive_ts()
      archive_root = run_dir / ".archived" / archive_ts
      archive_root.mkdir(parents=True, exist_ok=True)
      in_prog_fd = os.open(str(archive_root / ".in_progress"),
                           os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o644)
  ```

### F-11 · unlink/flock 释放分离导致残留误判 [concurrency + error_handling]

- 路径：`scripts/lib/workflow_rollback.py:737-754`
- critic verdict: `not_rebutted`
- 描述：mv 完成后 `in_progress_path.unlink(missing_ok=True)` 在 try 内（行 754），flock 释放在 finally。若 unlink 因权限/IO 失败抛 OSError，flock 仍释放但 `.in_progress` 残留 → 下次 rollback 走续跑路径误判崩溃。
- 修复建议：把 unlink 放进 finally 紧贴 flock 释放前；或将 unlink 失败包装成 RollbackError 上抛 + 显式 audit。

### F-19 · 续跑未恢复 to_node 元信息 [design_consistency + error_handling]

- 路径：`scripts/lib/workflow_rollback.py:553-624`（_resume_in_progress）+ `718-726`（主流程续跑分支）
- critic verdict: `not_rebutted`
- 描述：`_resume_in_progress` 强依赖调用方重传同一 to_node。`.in_progress` 用 O_EXCL 创建为空文件，未持久化首次 rollback 的 to_node。崩溃后用户若不知上次 to_node 即归档错乱（已 mv 的 A→tail 与新计算的 B→tail 混合）。
- 修复建议：首次 rollback 把 `{run_id, to_node, started_at}` 写入 `.archived/<ts>/.meta.json`；续跑时优先读 `.meta.json` 的 to_node，调用方传入与之不一致 → 拒绝。

### F-20 · 首次/续跑两路径 sub_run 发现策略不对称 [design_consistency + complexity]

- 路径：`scripts/lib/workflow_rollback.py:290-326`（`_collect_sub_run_ids` 续跑） vs `852-883`（`_find_matching_child_run_dirs` 首次）
- critic verdict: `not_rebutted`
- 描述：首次 rollback 优先 `run_dir/sub_runs/`；续跑用 `root/runs` + `root/requirements` 全扫 + 启发式 `child_dir.name in run_dir.name or nid in child_dir.name` 包含匹配。两路径归档结果集合可能不一致；短 run_id 还易误匹配。
- 修复建议：合并为单一发现策略 `_discover_sub_runs(run_dir, nodes_after) -> list[Path]`：(1) 优先读 run_state 元数据中的 sub_run id 列表；(2) 次选 `run_dir/sub_runs/` 直挂；(3) 命名约定退化为 fallback。`_collect_sub_run_ids` / `_find_matching_child_run_dirs` 合并删一。
