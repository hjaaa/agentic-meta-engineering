## Major（强烈建议修复）

### [security] .claude/workflows/requirement/standard-8phase.yaml:671

`$DRAFT_FLAG` 未加引号 + word-splitting；substitute_vars.escape_for_bash=True 把空值替成字面 `''`，gh 收到空字符串作位置参数。

**建议**：改为 `${DRAFT_FLAG:+--draft}` 条件展开（缺省时不写该参数），或 `[ -n "$DRAFT_FLAG" ] && DRAFT_ARGS=(--draft) || DRAFT_ARGS=()` 然后 `gh pr create ... "${DRAFT_ARGS[@]}"`。

### [concurrency] .claude/workflows/requirement/standard-8phase.yaml:666-673

pr-submit 裸调 `gh pr create` 无幂等保护；workflow 重试 / continue / 网络抖动会创建多个 open PR。submit-rules.md:87 已实现 `gh pr list --head <branch> --state open` 检查。

**建议**：bash 头加 `EXISTING=$(gh pr list --head "feat/req-$RUN_ID" --state open --json url --jq '.[0].url' 2>/dev/null); if [ -n "$EXISTING" ]; then PR_URL="$EXISTING"; else PR_URL=$(gh pr create ...); fi`。

### [concurrency / performance] .claude/workflows/requirement/standard-8phase.yaml:687-697

archive-finalize 5 次独立 `yq -i` 写 meta.yaml 无原子性 + 5 次 read-parse-write 同文件。中途崩溃会留 partial state（如 `archived_at` 已写但 `phase` 未写）。

**建议**：合并为单条 yq 表达式：`yq e '.archived_at = "..." | .outcome = "shipped" | .phase = "completed" | .workflow_status = "completed" | .completed_at = "..."' -i runs/$RUN_ID/meta.yaml`。

### [concurrency] .claude/workflows/requirement/standard-8phase.yaml:681-685

pr-merged-gate approval 节点缺 `on_reject` + `max_attempts`，与 gate_message 「如未合并请 reject 并继续等待」语义矛盾；其他 6 个 approval 节点都有完整 on_reject。reject 行为未定义可能终止整个 workflow。

**建议**：

```yaml
- id: pr-merged-gate
  approval:
    gate_message: |
      PR 已合并？请 approve 进入归档；如未合并请 reject 并继续等待。
    capture_response: true
    on_reject:
      prompt: |
        PR 尚未合并，请等待合并后再次 approve。当前 PR：$pr-submit.output.pr_url
      max_attempts: 10
  depends_on: [pr-submit]
```

### [error-handling] tests/workflows/test_prompt_structure.py:70-74

`_parse_frontmatter` 把 `yaml.YAMLError` 与无 frontmatter 都返回 `{}`；frontmatter 损坏时 test_frontmatter_parseable 失败诊断会写「缺少必填字段 name」而非「YAML 解析失败」。

**建议**：

```python
except yaml.YAMLError as e:
    print(f"WARN: frontmatter parse failed in {md_path}: {e}", file=sys.stderr)
    return {}
```

或直接 raise 让上层显式断言。

### [error-handling] .claude/workflows/requirement/standard-8phase.yaml:670-672

`PR_URL=$(gh pr create ...)` 后未校验 `$PR_URL` 非空；gh CLI 偶有 stdout 空但 exit 0 边界，会把空字符串写入 meta.yaml.pr_url，下游误读。

**建议**：在 PR_URL 赋值后立即 `[[ -z "$PR_URL" ]] && { echo "ERROR: gh pr create 未返回 PR URL（RUN_ID=$RUN_ID）" >&2; exit 1; }`。
