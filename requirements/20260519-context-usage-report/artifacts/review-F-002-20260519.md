## 建议（非阻断 follow-up）

- **F-002-S1 [minor · maintainability]** `_resolve_link`（`:68-87`）的"回退路径"在当前调用链上**实际不可达**。理由：
  - 调用方 `_check_index_file:110` 已用 `_is_external_or_intra_anchor(url)` 拦截了 外链 / intra-anchor / 空串
  - 进入 `_resolve_link` 的 url 只可能让 `_ml_resolve_link` 在 markdown_links.py:194-197（越界 ValueError）返回 None
  - 越界时回退构造的 `target` 也是越界路径，下游 `target.exists()` 仍为 False、报 `broken`——与"直接返回 `_ml_resolve_link` 的 None 然后调用方自己处理"的另一种实现等价
  - **建议**：F-008 文档同步阶段可将 `_resolve_link` 进一步收敛为单行 `return _ml_resolve_link(url, index_path, REPO_ROOT) or _fallback_target(url, index_path), anchor`，或在 wrapper 上方加注释说明"回退路径仅做向后兼容，在当前调用链下不可达"。不影响 F-002 关闭。

- **F-002-S2 [minor · testability]** F-001 review 的 follow-up F-001-S2 建议"F-002 之前补一组 `tests/test_markdown_links.py`"未落地。当前 F-002 的等价性保障完全依赖于 `tests/gates/test_index_integrity_plugin.py`（间接覆盖）+ 手工 diff（一次性）。若后续 F-003 / F-004 / F-005 继续基于 `markdown_links.py` 演进，缺少模块级单元测试会让回归成本变高。**建议**：在 F-008（文档同步）或更早的 light feature 里补 `tests/test_markdown_links.py`（mask_code_blocks 同长度 / extract_links 空文本 / resolve_link 越界 / slugify 中文 / glob_match `**` 至少 5 例）。不阻断 F-002。

## 跨维度洞察

- **wrapper 化是比"直删调用方"更稳的迁移姿势**。F-002 没有把 `_check_index_file` 内部所有 `_extract_links / _slugify / _resolve_link` 调用点全部改成 `_ml_*`，而是保留 thin wrapper、让外层调用点不动。好处：(a) 单次 commit 的 diff 范围最小，回归面收敛到 wrapper 层；(b) 若 markdown_links 后续微调返回类型（如 MarkdownLink 加字段），wrapper 是天然的"适配缓冲"。建议把这条 SOP 写入 `context/team/engineering-spec/` 的迁移类需求模板。

- **`extract_links` 的 fenced-code mask 是 F-001 引入的隐性能力增强**，在 F-002 切换后立即对 check_index.py 生效。当前仓库 INDEX.md 均未在 code block 内写 `[](...)`，因此 diff 为空；但**未来如果有人在 `context/INDEX.md` 的代码示例里写 markdown link，行为会发生变化（原版会报 broken，新版会忽略）**。这是改善而非回归，但应在 F-008 文档同步阶段于 `markdown_links.py` 模块文档显式提示，避免未来 debug 时困惑。
