### F-4 · `recency_score` 在 fs_mtime 回退时未归 0（设计偏离）

- **位置**：`scripts/lib/context_usage_report.py:200-204` + `:1185-1191`
- **根因**：`fetch_git_timestamps` 在 git log 成功但 since_days 窗外的 fallback 分支把 `last_commit_at = f.fs_mtime`（非 None），而 `_compute_score:1185-1191` 只判 `last_referenced_at is not None` 不判 `source`，导致 fs_mtime 来源仍触发 `recency_score=10/5`
- **设计要求**：`detailed-design.md:692` 明示 "recency_score = 0（fs_mtime 不参与 recency 计算）"
- **影响**：边界 case（since_days 默认 365 天，触发概率低）；触发时 fs_mtime 来源文件意外获得 recency 分，污染排序与状态分类
- **建议（二选一）**：
  - **(b) 推荐**：fallback 分支保持 `last_commit_at=None`，让 recency 自然为 0，与异常路径分支语义一致（fetch_git_timestamps 的异常 fallback 已是 last_commit_at=None）
  - **(a) 备选**：`_compute_score` 加 source 判定 `if source != 'fs_mtime'`，需把 source 传入 `partial` dict
