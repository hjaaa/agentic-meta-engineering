## Minor（改进建议）

### [security + error-handling] scripts/lib/context_usage_report.py:102

`scan()` 内 `path.resolve().relative_to(self._repo_root)` 对 symlink 文件存在两条 fail 路径：

1. `.md` symlink 指向 repo 外（如 `/etc/passwd.md`）→ `relative_to` 抛 `ValueError`（Python 3.12 之前无 `walk_up` 参数），单文件异常冒泡终止整次 scan，已扫描结果全部丢失
2. `.md` symlink 指向 repo 内非 `context/` 路径（如 `requirements/foo.md`）→ `relative_to` 不抛但被静默纳入统计，破坏"只统计 context/"边界约定

detailed-design.md:170-198 未对 symlink 场景做豁免；当前 test fixture（test_context_usage_report.py:30-50）不构造 symlink，该路径未被自动化覆盖。

**建议**：F-005+ 接入真实仓 `context/` 时，在 `scan` 循环里对 `resolve + relative_to + stat` 整段包一层 `try/except (OSError, ValueError)`，warning 日志 + 跳过单文件，避免一处 symlink 越界导致整次扫描中断。同时考虑构造时一次性 `context_dir.resolve()` + scan 内 `is_relative_to(self._context_dir_resolved)` 边界过滤，把"context/ 外"的 symlink 显式拦在统计外。
