### [security] scripts/lib/audit_flush.py:62, 96-99

**F-1：entry 字段路径穿越**

`_parse_lines:62` 仅做 `entry.strip()`，未过滤 `/` `..`；`_write_buckets:96-99` 直接把 entry 拼到文件名 `audit_dir / yyyy_mm / f"{entry}-{date}.json"`。POC 实测：

```bash
echo '2026-05-04T10:00:00 /repo event @ entry=../../evil' >> audit/.queue/2026-05-04.log
python3 scripts/lib/audit_flush.py
ls -la evil-2026-05-04.json   # 出现在 audit_dir 外
```

**建议修复**（成本 2 行）：在 `_parse_lines` 解析后加白名单 regex 校验：

```python
import re
ENTRY_RE = re.compile(r"^[A-Za-z0-9:_-]+$")
# in _parse_lines:
if not ENTRY_RE.match(entry):
    continue   # 跳过非法 entry 名整行
```

regex 与 `audit_async.sh::ENTRY_*` 常量集合（`runner` / `trigger:submit` / `pre-tool-use-guard` 等）天然吻合。

### [concurrency] scripts/lib/audit_flush.py:103-110, 147-166

**F-5：并发 flush 致 JSON audit 记录重复**

POC 实测 `python3 scripts/lib/audit_flush.py & python3 scripts/lib/audit_flush.py; wait` → audit/<entry>-<日期>.json 行数翻倍（5 行原始 → 10 行 JSON）。原因：P1/P2 同时 collect→parse→write→archive，第二次 mv 静默 fail 但 write 已 append 重复行。

**建议修复**（成本 5 行）：在 `_dispatch` 入口加非阻塞 fcntl.flock：

```python
import fcntl
def _dispatch(self, ...):
    lockfile = audit_dir / ".queue" / ".flush.lock"
    lockfile.parent.mkdir(parents=True, exist_ok=True)
    with lockfile.open("w") as _lock:
        try:
            fcntl.flock(_lock.fileno(), fcntl.LOCK_EX | fcntl.LOCK_NB)
        except (BlockingIOError, OSError):
            return 0   # 拿不到锁 → 让另一个进程做 → exit 0（D-005 best-effort）
        # ... 原 dispatch 逻辑 ...
```

F-6（dup<N> TOCTOU）随该锁自动消解。同时 test_audit_flush.py 必须补 multiprocessing 并发用例（F-7）防回归。
