### Carryover-1：F-3 [major] 变量间接引用绕过 12 类正则

**根因**：guard.sh / bash_write_protect.py 的 12 类正则都只匹配命令行中**字面量**出现的 review 路径。攻击/失误样例：

```bash
P=requirements/REQ-2026-006/reviews/x.json; echo data > "$P"
```

`>` 后是变量名 `$P` 而非字面量路径，grep 不命中，放行；shell 实际展开后写入 reviews/*.json。

**F-001 现状**：`bash_write_protect.py` 与 `pre-tool-use-guard.sh` 同设计都有此绕过；F-001 切换 settings.json 后 Python plugin 不再 live（见 carryover-2），**新 guard 是 live 路径唯一兜底**。

**F-002 删除 Python plugin 后**：单点防御永久化。

**F-002 必须在删除前选择决策（在 PR 描述中显式声明）**：

- **A. 接受单点防御**：在 `pre-tool-use-guard.sh` 12 类正则注释段加显式说明「变量间接引用是已知绕过通道；强约束在 BYPASS reason 长度 + audit reason 全文（已落地于 F-001 修复）+ PR review 检查」
- **B. 加强检测**：扩展 12 类正则覆盖 `\$\w+`、`\$\{[^}]+\}`、`$()` 包裹等变量引用形式（注：仍无法覆盖动态拼接，是猫鼠游戏；只是抬高门槛）
- **C. 推迟删 Python plugin**：F-002 仅删 `protect-branch.sh` / `pre_tool_use.sh` / `protect_branch.py`，保留 `bash_write_protect.py` 作 CI-only defense-in-depth；`registry.yaml` 中 GATE-BASH-WRITE-PROTECT 改为仅 `ci` trigger

> **推荐 A**：本需求设计目标是"收敛攻击面 + 简化"，C 与设计目标冲突；B 需要测试投入但价值有限。**A 配合 F-001 已落地的 BYPASS reason 长度 + audit 全文，加上 spec 显式声明，已是合理的 trade-off**。

**根因**：F-001 已把 PreToolUse hook 从 `protect-branch.sh`（→ `run.py --trigger=pre-tool-use` → Python plugin 全套）切到 `pre-tool-use-guard.sh`（纯 bash）。`bash_write_protect.py` 现在仅 CI 触发（`run.py --trigger=ci`），live Claude Code session 不跑。

**影响**：与 carryover-1 叠加放大攻击面（live 无 Python 兜底）。

**F-002 处置**：取决于 carryover-1 的决策选项。
