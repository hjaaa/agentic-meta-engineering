# F-003 · PR-3 CLAUDE_GATES_GLOBAL_BYPASS 三处入口（A1）

## 需求描述

全局逃生通道 PR——`guard.sh` / `run.py` / `submit.py` 三处入口检查 `CLAUDE_GATES_GLOBAL_BYPASS`。

具体动作：
- `guard.sh` 的 bypass 检查在 **F-001 中已含**（`.claude/hooks/pre-tool-use-guard.sh`）
- 本 PR 集中加 `run.py` + `submit.py` 两处：
  - `scripts/gates/run.py`：在第一个项目内 import（pathspec / yaml）之前加 bypass 块，写 `audit/.queue/<日期>.log` 一行后 `sys.exit(0)`（detail-design §3.1，避开 `from __future__` 边界）
  - `scripts/gates/triggers/submit.py`：顶部加 bypass 留痕（**仅写 audit 行，不 sys.exit**；继续走 run.py 让 run.py 顶部 bypass 兜底退出，避免双重退出语义混乱，detail-design §3.2）
- 三处 audit 行 entry 字段分别是 `pre-tool-use-guard` / `runner` / `trigger:submit`（呼应 outline-design §3 的 entry-name 约定 + detail-design 评审 R3 的 entry vs trigger 修订）
- 新增 `tests/gates/test_global_bypass.py` 5 用例（detail-design §3.3）

并行约束：本 PR 与 F-004 可并行——改 run.py 不同段落（顶部 import 块 vs main 函数体）；合并若有冲突 rebase 解决。

```python
# scripts/gates/run.py 顶部 bypass 块（在 from __future__ 之后、第一个项目内 import 之前）
if os.environ.get("CLAUDE_GATES_GLOBAL_BYPASS"):
    _reason = os.environ["CLAUDE_GATES_GLOBAL_BYPASS"]
    try:
        # append audit/.queue/<日期>.log: "<ts> <cwd> BYPASS used: <reason> @ entry=runner"
        ...

```

```python
# scripts/gates/triggers/submit.py 顶部 bypass 留痕（不退出）
if os.environ.get("CLAUDE_GATES_GLOBAL_BYPASS"):
    try:
        # append audit/.queue/<日期>.log: "<ts> <cwd> BYPASS noted: <reason> @ entry=trigger:submit"
        ...

        pass
    # 不 sys.exit；委托 run.py 顶部 bypass 退出
```
