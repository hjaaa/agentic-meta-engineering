## Major（强烈建议修复）

### [error-handling] `scripts/lib/workflow_run.py:113`

`logging.info('req_id=%s 顶层目录已创建', candidate_id)` 在每次创建 req_id 顶层目录时打 INFO。规范要求 INFO 仅用于业务节点（下单/支付/任务触发等）；本函数是底层工具，高频成功路径会污染生产日志。同文件 `_generate_run_id` 静默成功（line 62-63 仅 debug）。

**建议**：改为 `logging.debug(...)`，与 `_generate_run_id` 对称。

### [design-consistency] `tests/skills/test_workflow_commands.py` 缺 TC

`features.json` F-001 acceptance[2]：「max+1 策略与 _generate_run_id 一致；通过现有单测模式覆盖」。当前两个 TC：
- TC-F1-1：空目录 → REQ-{year}-001
- TC-F1-2：并发 3 线程 → 唯一性

**缺一条递增逻辑 TC**：已存在 `REQ-{year}-003` + `REQ-{year}-007` 时，调用 `_generate_req_id` 应返回 `REQ-{year}-008`。

**建议**：新增 TC-F1-3，3 行 fixture + 1 行断言即可。

## Minor（改进建议）

### [error-handling] `scripts/lib/workflow_run.py:120-122`
`raise WorkflowError(...) from None` 截断 FileExistsError cause chain，与 `_generate_run_id` 异常风格不对称（该处也未用 `from None`）。**建议**：去掉 `from None`，让原始错误透传。

### [error-handling] `scripts/lib/workflow_run.py:104`
WorkflowError 溢出消息仅含 ts_prefix（年份），不含 `max(nums)` 当前值。**建议**：拼入 `max(nums)`，便于 oncall 区分真溢出 vs 扫描偏差。

### [concurrency] `tests/skills/test_workflow_commands.py:850-851`
TC-F1-2 三线程顺序 `t.start()` 无同步起跑线，快机器上可能退化为准串行。**建议**：加 `threading.Barrier(3)` 真触发竞争。

### [design-consistency] `features.json` F-001 acceptance[1]
字面要求「并发 3 个**进程**」，TC-F1-2 实际用 `threading.Thread`。**建议**：把 acceptance 措辞改为「并发（线程/进程）」或 TC docstring 注明 threading 近似 mkdir 原子语义。

### [performance] `scripts/lib/workflow_run.py:90+`
`base.iterdir() + d.is_dir()` 对 requirements/ 每条目触发 stat；当前规模无问题，但需求累积上百目录后会退化。**建议**：改 `os.scandir()` + 名字 regex 预过滤。

### [aux] `scripts/lib/workflow_run.py:83 vs 36-43`
`_generate_req_id` docstring 含「抛出：」节，`_generate_run_id` docstring 无对应节，同文件 docstring 风格不齐。**建议**：`_generate_run_id` 补一行「抛出：WorkflowError 若超 _RUN_ID_MAX_RETRIES」。

### [aux] `tests/skills/test_workflow_commands.py:803/827`
`TestGenerateReqId` / `TestGenerateReqIdConcurrencySafe` 的 class docstring 含 `TC-F1-x：` 前缀，与同文件 TestHappyPath/TestCancelWritesEvent 等不一致（区块头注释已编号）。**建议**：改为纯功能描述。
