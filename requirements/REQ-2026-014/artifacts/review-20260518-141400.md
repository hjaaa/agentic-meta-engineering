## Major（强烈建议修复）

### [F-1] [concurrency + design-consistency] scripts/lib/worktree_manager.py:399-404

create_worktree exists 兜底匹配第三条 `"already exists" in stderr_trim` 过宽，可命中无关 git hook / 子命令 stderr 输出（如 "pre-commit hook: file already exists"），把 reason='other' 错升为 'path_or_branch_exists' 触发上层 retry 死循环；同时缺设计要求的 'fatal:' 前缀（features.json AC[3] / spec L425）。

**建议**：删去第三条泛化兜底；两条精确匹配补 'fatal:' 前缀，仅匹配 `fatal: '<path>' already exists` 与 `fatal: a branch named '<branch>' already exists` 两个明确字符串；不同 git 版本若措辞变化由单测捕获。

### [F-2] [error-handling] scripts/lib/worktree_manager.py:659/674

cleanup_worktree_if_owned docstring（L591-L592）承诺"git 失败 → CleanupResult(action='failed') + log ERROR；不抛异常，archive 主流程不受影响"，但两处 `_run_git` 调用未包 try/except；_run_git 在 FileNotFoundError / OSError / SubprocessError 路径仍可抛 WorktreeBootstrapError。

**建议**：二选一—
1. **推荐**：在两次 _run_git 外包 try/except WorktreeBootstrapError → 捕获即 return CleanupResult(action='failed', reason='git_failure', removed_path=None) + log ERROR；与设计意图"archive 主流程不受影响"对齐
2. 退而修改 docstring 改为"仅 git rc!=0 路径不抛，二进制丢失/OS 错误仍抛 BootstrapError"

### [F-3] [security] scripts/lib/worktree_manager.py:631

cleanup 保护2 用 `str(raw_path).startswith(str(raw_location))` 做路径白名单，对反向路径遍历 `.worktrees/../etc/passwd` 无防护——startswith 成立但实际逃出容器；若 meta.yaml 被外部污染（F-005 reload）可指向任意路径。

**建议**：改用 `(main_repo_root / raw_path).resolve().is_relative_to((main_repo_root / raw_location).resolve())` 做规范化对比；同时考虑把 location 硬编码为 `_DEFAULT_WORKTREE_DIR` 常量，不从 meta.yaml 信任读取，防止 meta 注入双字段绕过。

### [F-4] [error-handling] scripts/lib/worktree_manager.py:228-233

detect_worktree_state 中 `git rev-parse --git-common-dir` rc!=0 时静默 fallback 到 git_dir_raw，无任何日志；导致 git_dir==git_common_dir 恒成立，is_linked_worktree 永远 False，worktree 拓扑误判。可能掩盖 git 版本过旧 / 仓库损坏。

**建议**：rc!=0 时抛 WorktreeBootstrapError(reason='other') + stderr trim 透传；或至少加 logging.debug 记录 fallback。不允许覆盖式静默兜底。
