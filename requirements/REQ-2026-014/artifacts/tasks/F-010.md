## 需求描述

改 context/team/engineering-spec/meta-schema.yaml：在 fields: 段追加 worktree 一组定义（顶层 optional；与 detailed-design §2.1 字段表 + schema fragment 12 字段全集一一对应：enabled / owner / path / absolute_path / branch / base_branch / created_at / baseline.{command,status,completed_at} / cleanup.{policy,removed_at}）。P1-4 修复采用**最小改动**：现有 check_meta.py 只消费 required_fields / enums / format / conditional_required 四类规则，**不发明** `nullable: true` / `type: [string, "null"]` 等 schema 语法；removed_at 在 schema 中保持 `type: string, required: false`，canonical unset 形式 = 空串 `""`（archive 未发生时 F-008 模板初值；cleanup 成功后 F-005 回填 ts）；legacy meta 缺段走 `meta.get("worktree", {})` 防御性短路，不引入 null。conditional_required 不强制 worktree 段必填（旧需求兼容，缺则默认 enabled=false）。新增 tests/lib/test_meta_schema_worktree.py 在 schema checker 之外另起一组 worktree-meta 单测，覆盖：含 worktree 段的 meta.yaml 校验通过；worktree.owner 取非法枚举值时校验失败；worktree.cleanup.removed_at 取空串 OR 合法 ts 均通过（不测 null 形式——若未来要强校验'空串或合法 ts'二者择一，在本 checker 内补单测，不扩展 meta-schema.yaml 语法）；缺 worktree 段的 legacy meta.yaml 校验通过。落地 outline-design §OD-3 决议 + spec §5.2 + tech-feasibility §1.5 R7 缓解。
