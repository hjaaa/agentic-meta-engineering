### [G-2] [security] scripts/lib/worktree_manager.py:676-694

cleanup_worktree_if_owned `raw_location` 仍取自 `worktree_meta.get("location", _DEFAULT_WORKTREE_DIR)`，attacker 同时设置 meta.yaml.worktree.{path: "/etc/passwd", location: "/"} 时 `Path("/etc/passwd").is_relative_to(Path("/"))` 恒真，绕过保护 2 白名单。仅保护 3（main_root != worktree_path）兜底单点。

**rev1 F-3 已识别但归 suggestion，rev2 未采纳——trend-G-meta「修一半」范式**

**建议**：将 `raw_location` 硬编码为 `_DEFAULT_WORKTREE_DIR` 常量，不从 meta.yaml 信任读取：
```python
# 不信任 meta.location，固定锚定到主仓 .worktrees/
resolved_location = (main_repo_root / _DEFAULT_WORKTREE_DIR).resolve()
```
或保留 meta.location 但额外校验 `resolved_location.is_relative_to(main_repo_root.resolve())`：
```python
if not resolved_location.is_relative_to(main_repo_root.resolve()):
    is_in_whitelist = False
```
