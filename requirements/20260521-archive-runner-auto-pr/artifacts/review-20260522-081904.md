## Major（强烈建议修复）

### [security] scripts/lib/archive_runner.py:595

`_push_feat_branch` 的 `git push origin <branch>` 无 `_PROTECTED_BRANCHES` 白名单 + refspec 字符校验。对比：

- `_delete_local_branch:625` 有 `_PROTECTED_BRANCHES` 防御
- `_delete_remote_branch:745` 有 `_PROTECTED_BRANCHES` 防御
- `_push_feat_branch:595` 无任何防御 ← 不对称

`meta.branch` 被污染时可触发 `+HEAD:refs/heads/develop` 强推或 `:develop` 删除等 refspec 注入；攻击面虽小（用户自己控制 meta），但作为远程写操作的第二道防线是必备的。

**建议**：抽 `_validate_branch_for_remote_op(branch)` helper，统一三处远程 git 写操作的 branch 白名单/refspec 字符检查：

```python
def _validate_branch_for_remote_op(branch: str, req_id: str, error_code: str) -> None:
    if branch in _PROTECTED_BRANCHES or branch.startswith('-') or ':' in branch:
        _abort(error_code, f"非法 branch 名: {branch!r}", req_id)
```

### [error-handling] scripts/lib/archive_runner.py:509,517,552,561,581,590,595

`_commit_archive_metadata` + `_push_feat_branch` 共 **7 处** `_run()` 调用缺 `try/except (subprocess.TimeoutExpired, FileNotFoundError, OSError)`，与同文件 `_precheck_pr_merged:301-310` 模式不对称：

- `TimeoutExpired` 抛出会以 unhandled traceback 形式 crash，**绕过** `R-ARCHIVE-COMMIT-FAILED` / `R-ARCHIVE-PUSH-FAILED` 错误码契约
- 详细设计 §1.2 / §1.3 明确给出这两个错误码作为 fail-closed 出口，但当前实现让 timeout / git not found / OSError 三类异常逃出错误码体系

**建议**：抽 `_run_or_abort(cmd, *, cwd, error_code, req_id, label)` helper，内部 try/except → `_abort` 兜底，统一替换 7 处裸 `_run`。
