# F-001 · routing.py 核心引擎（yaml 加载 + schema 校验 + pathspec 匹配）

## 需求描述

实现 `scripts/lib/code_review_routing.py` 的**核心数据模型与无 IO 计算层**。本 feature 聚焦"纯函数 + dataclass"层，不涉及 tty / stdin / 写盘 / process.txt / git diff——这些 IO 副作用全部留给 F-002。完成后通过 12 条单元测试（U1-U10 + U-INV-1）覆盖所有边界。

## 接口/数据结构

详见 `requirements/REQ-2026-003/artifacts/detailed-design.md`：

- §2.1 模块级常量 + 5 类异常体系（`RoutingError` 基类 + `RoutingYamlError` / `RoutingSchemaError` / `RoutingTTYError` / `RoutingAbort`，5 个退码常量 EXIT_OK..EXIT_USER_ABORT）
- §2.2 dataclass：`MatchResult` / `RoutingPlan`（含 INV-PLAN-1..4 不变量）/ `RoutingDecision` / `_RuleEntry` / `RoutingConfig`
- §2.4 无 IO 函数签名：`_load_yaml` / `_validate_schema` / `_enumerate_diff_files` / `_build_plan`
- §7 退码 3 vs 4 精确分界（_load_yaml 抛 4，_validate_schema 抛 3）
- §3.3 `skipped_checkers.reason` 三选一模板（_build_plan 出口决定）

**关键不变量**（INV-PLAN-1..4，需在 `_build_plan` 出口 + 单测 U-INV-1 双重保证）：

```
INV-PLAN-1: set(files_must_hit.keys()) == must_checkers
INV-PLAN-2: set(files_suggest_hit.keys()) == suggest_checkers
INV-PLAN-3: must_checkers ⊆ ALL_CHECKERS ∧ suggest_checkers ⊆ ALL_CHECKERS
INV-PLAN-4: trivial_only=True ⇒ must/suggest 全空 ∧ files_trivial == files_total > 0
```
