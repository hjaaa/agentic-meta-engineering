## 开发笔记

**关键 pitfall**：

- benchmark 的 B3 用例（2000 文件）应使用真实仓库 diff 模拟，而非合成；`requirement.md:73` 上限 2000 是设计目标。
- 防御性 contract test 不要求修改 critic / judge / report 内部逻辑——它们在 F-003 后已通过 `commands/code-review.md` Step 2 的 `if scope.skipped == true: return` 自动短路；本 feature 的 contract test 只是把 skipped scope 直接喂给三个 Agent / SKILL，确保它们即便被误调用也不崩溃（防御性，对未来重构兜底）。
- pytest-benchmark 在 CI 不强制：用 `@pytest.mark.benchmark` 标记，CI 默认 `-m "not benchmark"` 跳过。
- E2E 测试发现 routing.py main() 步骤 2 为 tty 检查，早于步骤 3（yaml 加载）和步骤 4（schema 校验）；因此 E3/E4 无法通过 CLI 主入口测试，改为直接调用内部函数 `_validate_schema`/`_load_yaml` 验证退码语义。

**benchmark 实测 P95（本机 macOS Apple Silicon，2026-05-01）**：

| 用例 | 文件数 | 路径类型 | Mean | P95 估算 | 规格上限 |
|------|--------|---------|------|----------|---------|
| B1   | 50     | trivial-only | ~0.45ms | < 1ms | 100ms |
| B2   | 200    | mixed（must+trivial+灰色）| ~1.4ms | < 3ms | 200ms |
| B3   | 2000   | mixed（must+trivial+灰色）| ~12.6ms | < 15ms | 200ms |

三档均远低于规格上限，_build_plan 的 pathspec 实现性能充裕。

**E2E 用例实际行为**：

- E1 SKIP：pty 子进程在 bash 内复杂，已由 test_code_review_routing.py 的 TestPtyIntegration 覆盖（T1-T3）
- E2 PASS：构造 5 个 docs/*.md trivial 文件的 git diff，调用 _build_plan 验证 trivial_only=True + files_total=5
- E3 PASS：写入 6 条 must 规则的 routing.yaml，调用 _validate_schema 验证抛出 RoutingSchemaError（exit_code=3）+ detail 含 "V3"
- E4 PASS：写入不合法 yaml，调用 _load_yaml 验证抛出 RoutingYamlError（exit_code=4）

**contract test 覆盖点**：

- T-CRITIC-1（5 tests）：合法 JSON 序列化/反序列化；I7（checker_route=[] ∧ skipped_checkers==8）；I8（总 checker 数=8）；reason 固定模板；all_eight_checker_names 与 ALL_CHECKERS 一致
- T-JUDGE-1（5 tests）：合法 JSON；routing_decision.decision='trivial-skipped'；checker_route=[]；tty_verified=True；skipped 字段一致性
- T-REPORT-1（4 tests）：合法 JSON；commands/code-review.md 短路逻辑 grep；skipped_checkers 字段存在；三字段联合一致性
