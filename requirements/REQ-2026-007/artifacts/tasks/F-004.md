# F-004 · submit --codex 子模式 + codex-reviews 子目录 + V-09 常量验收

## 需求描述

- 改 `.claude/commands/requirement/submit.md` 参数表加 `--draft` / `--codex` / `--codex-poll-interval` / `--codex-timeout`（detail-design §3.4.1）；`--codex-*` 必须与 `--codex` 同传，否则 exit 1
- 改 `.claude/skills/managing-requirement-lifecycle/reference/submit-rules.md`：顶部三常量集中段（§3.3.2）+ 第 7.5 步 codex 单轮子模式细则（§3.6 状态机骨架展开）
- Skill 实现 `submit_with_codex`（§3.3 签名 + `CodexRoundResult` dataclass）：
  - 发 `@codex review` 评论 → `time.monotonic` 轮询
  - 命中按三因子：`user.type=Bot` && `/codex/i.test(login)` && `submitted_at>triggered_at`
  - 429 → timeout 不重试（spec §10）
  - 三 verdict 全 exit 0，stderr 关键串区分（§3.3.1）
- 新增 `requirements/<id>/artifacts/codex-reviews/round-N.md` 写盘逻辑（§4.2 frontmatter）+ round 号 = 已有 `round-*.md` 数 + 1（不允许跳号/重号）
- 改 `requirement-progress-logger` SKILL.md 白名单加 `[codex-review-triggered]` / `[codex-review-received]`（§4.3）
- 新增 `tests/lifecycle/test_submit_codex.py`：mock gh CLI 覆盖 passed / not_passed / timeout / 429 / round 自增
- V-09 常量验收：grep 全仓 `Didn't find any major issues.` 仅在 submit-rules.md 一处

## 接口/数据结构

- `submit_with_codex(req_id: str, *, poll_interval_s: int = 5, timeout_s: int = 600) -> CodexRoundResult`
- `CodexRoundResult` dataclass：`verdict: Literal['passed','not_passed','timeout']` / `round: int` / `triggered_at` / `received_at` / `review_url`
- 三常量集中：`CODEX_REVIEWER_USER_TYPE = "Bot"` / `CODEX_REVIEWER_LOGIN_PATTERN = r"codex"i` / `CODEX_PASS_PHRASE = "Didn't find any major issues."`
- 命令行参数：`--codex` (boolean) / `--codex-poll-interval N` / `--codex-timeout N`（后两者依赖 --codex）
- round-N.md frontmatter（passed/not_passed 8 字段；timeout 仅 round/triggered_at/verdict 三字段）
