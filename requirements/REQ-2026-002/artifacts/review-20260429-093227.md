### [concurrency + test_coverage · G-3] scripts/gates/run.py:452-465 + tests/gates/test_run_force_with_blockers.py

`_handle_escape_hatch` 命中 force_used=True 后直接 `return True, False`，**未清理**：
1. `snapshots` 中的 .bak 快照（应调 `_cleanup_snapshots(snapshots)`）
2. `ctx.staged_writes` 暂存写操作（应调 `ctx.staged_writes.clear()`）

注释自承"已跳过 rollback"暗示了这点但未实施。8 个新单测无一覆盖此场景（grep `snapshots` / `staged_writes` / `.bak` 0 命中）。

**影响**：每次 force-with-blockers 触发后 .bak 残留在 `requirements/<req-id>/` 工作区；并发场景下两进程同时进 force 路径会出现 .bak 覆盖竞争；ctx 复用场景下 staged_writes 残留可能误提交。

**建议**：
```python
def _handle_escape_hatch(ctx, gate_fail, executed, snapshots):
    if force_used:
        _cleanup_snapshots(snapshots)
        ctx.staged_writes.clear()
        return True, False
    ...
```
新增单测：`test_force_with_blockers_cleans_snapshots`（构造含 .bak 的 plan + force 触发，断言 .bak 已删 + staged_writes 已空）。

### [error_handling + design · G-5] scripts/gates/run.py:378/385/396

reason 校验失败用 `return 1`，但 run.py:134 docstring 自定义退出码契约：「1 = 含 error 级 fail / 2 = 非法 trigger / 非法 requirement_id / runner 自身异常」。reason 是同等级 CLI 入参非法（与 trigger / req-id 同类），应归 `return 2`，与 `_resolve_trigger` 的 `SystemExit(2)` 一致。

**建议**：3 处 `return 1` 改 `return 2`；同步 4 个测试 `test_force_with_blockers_empty_reason` 等的断言。
